# 다이어리 비서

사용자가 말로 던지는 하루를 `diary/YYYY-MM-DD.md`에 정리하고, 되돌아보게 해 주고,
마감이 가까운 일을 먼저 알려 주는 스킬. 파일은 사람이 직접 열어 고쳐도 되는 평범한 마크다운이다.

기준 폴더는 이 저장소 루트(`my-diary`)다. 아래 경로는 전부 루트 기준 상대경로로 쓴다.

## 절대 규칙 — 무엇을 건드리고 무엇을 안 건드리나

프로젝트 `CLAUDE.md`에는 "요청 범위 밖의 파일을 임의로 만들지 않는다"는 규칙이 있다.
**이 스킬은 그 규칙의 명시적 예외다.** 사용자가 이 스킬을 만든 목적 자체가
`diary/` 아래에 날짜별 파일을 만들고 덧붙이는 것이므로, 다음은 매번 허락을 다시 묻지 않는다.

- 만들어도 되는 것: `diary/` 폴더, `diary/YYYY-MM-DD.md` 파일, 그 파일 안의 줄.
- **그 외에는 아무것도 만들거나 고치지 않는다.**

특히 다음 파일은 **읽기만 하고 절대 수정하지 않는다.** 사용자가 "다이어리에 반영해줘"라고 말해도
그 대상은 언제나 `diary/` 아래 파일이지 사이트 파일이 아니다.

- `index.html`
- `about.html`
- `index.backup-20260908.html`
- `CLAUDE.md`, `HANDOFF.md`

사이트(`index.html`)는 브라우저 localStorage에 따로 데이터를 갖고 있다.
**이 스킬의 파일과 사이트 데이터는 서로 동기화되지 않는다.** 둘을 맞추려 하지 말고,
사용자가 물으면 지금은 따로 논다고 사실대로 말한다.

## 항상 먼저 하는 일 — 오늘 날짜 확인

어떤 모드든 **추측하지 말고 셸로 오늘을 확인하고 시작한다.**

```bash
date +'%Y-%m-%d %u'
```

`%u`는 요일 번호다: `1=월 2=화 3=수 4=목 5=금 6=토 7=일`.
파일 제목에 넣을 한글 요일은 이 번호로 직접 대응시킨다. `date +%a`는 영어(`Wed`)가 나오므로 쓰지 않는다.

## 파일 형식

파일명은 `diary/YYYY-MM-DD.md`. 새 파일의 원형은 이것뿐이다.

```markdown
# 2026-09-30 (수)

## 기록

## 할 일
```

- 두 구획은 비어 있어도 항상 둔다.
- 기록 줄: `- 팀 회의 3건`
- 할 일 줄: `- [ ] 보고서 초안 (마감: 2026-10-02)`
- 마감 없는 할 일: `- [ ] 방 정리` (괄호를 아예 안 쓴다)
- 완료: `- [x] 보고서 초안 (마감: 2026-10-02)` — 마감은 지우지 않고 남긴다
- `(마감: ...)`은 **항상 줄 맨 끝**, 날짜는 **항상 절대 `YYYY-MM-DD`**.
  "금요일", "내일" 같은 표현이 파일에 남으면 안 된다.
- 제목 줄의 요일은 사람이 보라고 넣는 장식이다. **판단 기준은 언제나 파일명**이고 제목은 파싱하지 않는다.
- `## 마감` 구획은 만들지 않는다. 마감은 할 일 줄에만 있고, 모드 3이 그때그때 모아서 보여 준다.

## 모드 판별

사용자 말 한 덩어리를 받으면 셋 중 하나로 고른다.

1. **정리(모드 1)** — 새로운 사실이나 할 일이 들어 있다. "오늘 ~했어", "~까지 해야 해", "적어둬".
2. **요약(모드 2)** — 이미 적은 것을 물어본다. "뭐 했지", "정리해줘", "요약", "어땠어".
3. **마감(모드 3)** — 남은 일이나 급한 일을 물어본다. "마감", "급한 거", "남은 거".

애매할 때의 규칙:

- **기록과 마감이 한 문장에 섞였으면 모드 1이고, 두 줄로 쪼개 각 구획에 넣는다.**
  예) "오늘 회의 3개 했고 보고서 금요일까지야" → 기록 1줄 + 할 일 1줄.
- **"오늘 정리해줘"는 양쪽으로 읽힌다.** 앞에 새 내용이 없으면 요약(모드 2), 새 내용이 붙어 있으면 정리(모드 1)다. 정말 모르겠으면 한 줄로 되묻는다.
- **"이거 끝냈어" 류는 정리가 아니라 완료 처리(모드 1-b)다.** 새 줄을 추가하면 안 된다.
- 어느 쪽도 아니면 스킬을 쓰지 말고 평소대로 답한다. 다이어리와 무관한 잡담까지 파일에 적지 않는다.

## 모드 1 — 정리

### 1) 오늘 날짜를 확인한다

```bash
date +'%Y-%m-%d %u'
```

### 2) 상대 날짜를 절대 날짜로 바꾼다

"금요일", "내일" 같은 말은 **파일에 쓰기 전에 반드시** 절대 날짜로 바꾼다. 암산하지 말고 셸로 계산한다.

- 오늘/내일/모레/글피 → `date -d "+0 days"` / `+1` / `+2` / `+3`
- **요일만 말한 경우(예: "금요일")** → **오늘을 포함해 앞으로 가장 먼저 오는 그 요일.**
  목표 요일 번호를 `T`(월=1...일=7), 오늘을 `U`라 할 때:

  ```bash
  U=$(date +%u); T=5; D=$(( (T - U + 7) % 7 )); date -d "+$D days" +%Y-%m-%d
  ```

  오늘이 토요일(U=6)이고 "금요일"이면 D=6, 즉 **이번 주가 아니라 다음 금요일**이 된다. 이게 의도한 동작이다.
  `date -d "next friday"` 같은 영어 표현은 해석이 갈리므로 쓰지 않는다.
- "이번 주 금요일" → 이번 주 월요일 + 4일
- "다음 주 월요일" → 이번 주 월요일 + 7일
- "이번 주까지" → 이번 주 일요일
- "10일까지" → 이번 달 10일. 이미 지났으면 다음 달 10일.
- "월말" → `date -d "$(date +%Y-%m-01) +1 month -1 day" +%Y-%m-%d`

이번 주 월요일:
```bash
U=$(date +%u); date -d "-$((U-1)) days" +%Y-%m-%d
```

**해석이 두 가지 이상으로 갈리면 추측하지 말고 되묻는다.** 다만 되묻는 대신 확인 메시지에
근거를 같이 보여 주는 쪽을 우선한다(아래 5번).

### 3) 기록인지 할 일인지 가른다

- **끝난 사실** → 기록. "했어", "갔다", "만났다", "읽었다", "봤어"
- **앞으로 할 일이나 의무** → 할 일. "해야 해", "할 거야", "하기로 했어", "~까지"
- **마감 표현이 붙어 있으면 무조건 할 일**이고 `(마감: ...)`을 단다.
- 한 문장에 둘 다 있으면 **쪼개서 각각 넣는다.**
- **애매하면 기록에 넣는다.** 잘못 들어간 기록은 무해하지만, 잘못 들어간 할 일은 마감 목록을 오염시킨다.
- 사용자가 한 말을 그대로 옮기되 문장은 짧게 다듬는다. 없는 내용을 지어내지 않는다.

### 4) 파일에 덧붙인다 — 기존 내용을 절대 덮지 않는다

1. `diary/` 폴더가 없으면 `mkdir -p diary`.
2. 대상 파일을 **먼저 Read 한다.**
3. **파일이 없을 때만** Write로 원형과 내용을 새로 쓴다.
4. **파일이 이미 있으면 절대 Write 하지 않는다. 반드시 Edit로 줄을 끼워 넣는다.**
   - 기록 추가: `## 할 일` 줄 바로 앞에 넣는다.
   - 할 일 추가: 파일 맨 끝에 붙인다.
   - 셸 리다이렉션은 쓰지 않는다.
5. **중복 방지**: 같은 날 파일에 글자가 같은 열린 할 일이 이미 있으면 새 줄을 만들지 말고
   기존 줄의 마감만 고친다.
6. 원칙적으로 대상은 **오늘 파일**이다. "어제 ~했었지"처럼 과거 날짜가 분명하면 그 날짜 파일에 넣되,
   확인 메시지에 어느 날짜 파일인지 반드시 밝힌다.

### 5) 되돌려 확인한다

무엇을 어디에 넣었는지, **상대 날짜를 무엇으로 해석했는지**를 같이 보여 준다.
말투는 반말이되, 파일에 들어가는 문장은 평범한 서술체로 쓴다.

```
2026-09-30 (수)에 정리했어.

기록
- 팀 회의 3건

할 일
- [ ] 보고서 초안 (마감: 2026-10-02)   <- "금요일"을 이렇게 읽었어

마감 임박
- D-2 (금, 2026-10-02) 보고서 초안
```

해석 근거를 남기는 게 핵심이다. 틀렸으면 사용자가 그 자리에서 잡아낸다.

## 모드 1-b — 완료 처리

"이거 끝냈어", "보고서 다 했어" 같은 말은 **새 줄을 추가하는 게 아니라 기존 줄을 고치는 일**이다.

1. Grep 툴로 `^- \[ \] ` 를 `diary/*.md` 전체에서 찾아 해당 항목을 찾는다.
   (옛날 날짜 파일에 있을 수 있으니 오늘 파일만 보면 안 된다.)
2. 후보가 여러 개면 목록을 보여 주고 고르게 한다. 짐작해서 하나를 고르지 않는다.
3. **그 항목이 원래 적혀 있던 파일에서** Edit로 `- [ ]` 를 `- [x]` 로 바꾼다. 마감 문구는 그대로 둔다.
4. 못 찾으면 그런 항목이 없다고 말하고 새로 적을지 묻는다. 마음대로 새로 만들지 않는다.

## 모드 2 — 요약

**이 모드는 아무것도 쓰지 않는다. 완전한 읽기 전용이다.**
요약 결과를 다시 파일에 적지 않는다. 적으면 다음 요약이 요약을 또 요약하게 된다.
사용자가 굳이 저장을 원하면 어디에 남길지 먼저 묻는다.

### 기간 정하기

- "오늘 뭐 했지" → 오늘 파일 하나
- "어제" → 어제 파일 하나
- **"이번 주" → 월요일부터 일요일까지** (`date +%u` 기준, 위 공식)
- "지난주" → 이번 주 월요일에서 7일 전부터 1일 전까지
- "이번 달" → `diary/YYYY-MM-*.md`

### 파일 모으기

```bash
ls diary/*.md 2>/dev/null
```
로 실제 있는 파일을 먼저 확인하고, 기간에 해당하는 것만 Read 한다.

- **없는 날은 조용히 건너뛰되, 몇 개를 읽었는지는 밝힌다.** 예) 7일 중 4일 적혀 있었어.
- **없는 날의 내용을 지어내지 않는다.**
- 기간에 파일이 하나도 없으면 그 기간엔 적은 게 없다고만 말한다.

### 출력 모양

```
이번 주 (2026-09-28 월 ~ 2026-10-04 일) — 7일 중 2일 기록

마감 임박
- 마감 지남 (2026-09-29) 전기요금 납부
- D-2 (금, 2026-10-02) 보고서 초안

한 일
- 월: 전기요금 고지서 확인
- 수: 팀 회의 3건, 저녁 운동

끝낸 일 1개 / 남은 일 2개
```

마감 블록이 비어 있으면 그 블록 자체를 아예 출력하지 않는다.

## 모드 3 — 마감 임박

### 1) 기준표를 먼저 만든다 (날짜 암산 금지)

```bash
for i in 0 1 2 3; do echo "D-$i $(date -d "+$i days" +%Y-%m-%d)"; done
```

이 표만 있으면 D-n 계산이 **문자열 대조**로 끝난다. 예(2026-09-30 기준):

```
D-0 2026-09-30
D-1 2026-10-01
D-2 2026-10-02
D-3 2026-10-03
```

### 2) 전체를 훑는다

Grep 툴로 `diary/*.md` 전체에서:

```
^- \[ \] .+ \(마감: [0-9]{4}-[0-9]{2}-[0-9]{2}\)$
```

완료(`- [x]`)는 잡히지 않으므로 자동으로 빠진다. 같은 내용이 여러 날 파일에 중복돼 있으면 한 번만 보여 준다.

### 3) 분류한다 — 세 통

`T`를 오늘, `L`을 D-3 날짜라 할 때, 마감일 `X`를 문자열로 비교한다.

- `X`가 `T`보다 앞 → **지남**
- `T`부터 `L` 사이 → **임박** (D-0 ~ D-3)
- `L`보다 뒤 → **나중** (기본으로는 출력하지 않고, 물어보면 보여 준다)

임박 기준 D-0~D-3(오늘·내일·모레·글피)은 이 프로젝트에서 이미 정한 "마감 3일 전부터" 규칙을 따른 것이다.

### 4) 정렬과 표기

**지남(오래된 것부터) → 임박(D-0에서 D-3 순) → 나중(요청 시)** 순서.

- 지남: `마감 지남 (2026-09-29) 전기요금 납부`
- 임박: `D-2 (금, 2026-10-02) 보고서 초안`
- D-0은 `D-0 (오늘, 2026-09-30)`, D-1은 `(내일, ...)`, D-2는 `(모레, ...)`, D-3은 `(글피, ...)`로 써도 된다.

### 5) "먼저 알려주기"를 어떻게 지키나

**마감 블록은 언제나 응답의 맨 위, 다른 내용보다 먼저 출력한다.** 다음 경우에 붙인다.

- 모드 1 정리를 끝낸 직후
- 모드 2 요약의 맨 앞
- 모드 3 질문에 답할 때
- 한 세션에서 이 스킬을 처음 쓸 때 1회

**지남과 임박 항목이 하나도 없으면 블록을 통째로 생략한다.** 마감 없음 같은 빈 머리말을 찍지 않는다.
다이어리와 무관한 대화에까지 마감을 들이밀지 않는다.

## 말투

- 사용자에게 하는 말은 **반말**로, 짧고 담백하게. 과장하거나 칭찬하지 않는다.
- **파일에 쓰는 문장과 커밋 메시지는 반말을 쓰지 않는다.** 평범한 서술체로 짧게 쓴다.
- 이모지는 쓰지 않는다.
